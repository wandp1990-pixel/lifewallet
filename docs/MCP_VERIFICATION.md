# MCP 확장 검증 기록

검증일: 2026-10-21 (Asia/Seoul).

모든 변경 검증은 실행 전에 TURSO_DATABASE_URL을 임시 SQLite 파일로 지정하고 실제 TURSO_AUTH_TOKEN을 제거했다. 운영 배포, 운영 데이터 변경, 실제 데이터 이관은 실행하지 않았다. HTTP 검사는 로컬에서 생성한 테스트 세션/키와 임시 DB로 프로덕션 빌드의 standalone 서버를 실행했다.

| 검사 | 결과 |
| --- | --- |
| npx tsc --noEmit | 통과 |
| npm test | 기존 재무 보고서 33 pass / 0 fail |
| npm run test:mcp | 기존 영수증·확장 장부·OAuth·자산 삭제 검사 모두 통과 |
| npm run build | 격리된 DB로 프로덕션 빌드 통과 |
| npm run test:mcp:http | 빌드된 서버에서 로그인/권한/저장/조회/수정/삭제 흐름 통과 |
| git diff --check | 통과 |

HTTP 검사는 .next/standalone/server.js가 있어야 실행된다. 빌드도 initDb를 실행하므로 [배포 안내](WORK_MCP.md)의 검증용 환경을 먼저 지정해야 한다. 최초 샌드박스 빌드의 포트 바인딩 제한은 허용된 네트워크 실행 환경에서 해결했고, 실제 HTTP 검사에서 발견한 Next 내부 호스트 정규화와 출처 비교 문제를 수정한 뒤 빌드/HTTP 검사를 통과했다.

## 예시 및 데이터 정합성

별도 임시 장부의 자동이체 계좌는 전일 100만 원, 비상금은 전일 0원, 햇살론은 전일 600만 원 부채로 시작했다.

| 사용자 의도 | 확인한 결과 |
| --- | --- |
| 오늘 급여 280만 원 입금 | 실제 수입 거래 ID 저장, 자동이체 잔액 380만 원 |
| 오늘 비상금 잔액 35만 원 | 거래 생성 없이 잔액/기준일 갱신 |
| 개인차입금 오늘 550만 원 남음 | 저장 부채 -5,500,000원, 수입/지출 변화 없음 |
| 자동이체→비상금 10만 원 | 동일 날짜의 기준 잔액 포함 여부 질문. 미포함 확인 후 자동이체 370만 원, 비상금 45만 원 |
| 햇살론 원금 10만+이자 8천 상환 | 출금 108,000원, 부채 원금만 100,000원 감소 |
| 15,000원 식비 두 건 중 한 건을 12,000원으로 변경 | 여러 후보이면 AMBIGUOUS_TARGET 및 실제 후보 ID 반환, 선택 후 차액 3,000원만 잔액 복원 |
| 같은 등록·수정·삭제 요청 재시도 | 원래 결과/ID 재생, 거래 및 잔액 추가 반영 없음 |
| 다른 사람의 ID 지정 | ID 조회 전 타 계정 차단 또는 인증된 소유자 장부에서 NOT_FOUND |

식비 두 건 중 한 건 수정 시 조회 전체 합계는 수입 2,800,000원, 일반 지출 27,000원, 상환 원금 100,000원, 이자 8,000원, outflow 135,000원이다. limit=1과 다음 페이지의 합계가 동일했다. 이때 비상금 포함 자산 총액은 4,015,000원, 부채 11,400,000원, 순자산 -7,385,000원, 소비 spending은 35,000원으로 검증했다.

등록→조회→수정→재조회→삭제 후 자동이체 계좌는 최초 100만 원, 햇살론은 최초 600만 원 부채로 돌아왔다. 직접 설정한 기준 잔액은 이력으로 남고 수입·지출에는 섞이지 않는다. 기준일 이전/당일 거래 수정과 직접 재설정 후 삭제도 이중 취소하지 않는지 검사했다.

동시 동일 요청, 동일 키의 다른 입력 충돌, 기존 영수증 재시도 테이블 호환, 강제 감사 저장 실패 시 전체 롤백, 앱 REST Idempotency-Key, 기준일 이전 잔액의 null 처리, KST 자정, 삭제 거래 원래 ID 복구 및 삭제 이후 새 기준점이 생긴 경우의 복구도 통과했다.

기존 앱의 현재 잔액 입력과 MCP의 as_of 잔액 입력 계약도 따로 검증했다. 기준일 이후 거래가 있는 계좌를 앱에서 현재 200만 원으로 수정하면 200만 원을 그대로 유지하고, MCP에서 전일 기준 150만 원으로 수정하면 이후 거래만 추가한다. 실제 HTTP 검사도 앱 현재 잔액 재전송이 기존 급여를 두 번 더하지 않는지 확인한다.

## 인증과 실제 HTTP

- Google 외부 호출 없이 fixture 로그인으로 OAuth discovery, DCR, 서명된 로그인/동의, PKCE, 코드 일회 사용, JWT 읽기·쓰기, refresh rotation을 검증했다.
- 조회 전용 JWT는 모든 쓰기 도구에서 403이었다. 다른 계정의 유효한 세션/허용되지 않은 소유자는 18개 MCP 도구와 앱 40개 API 메서드에서 차단됐다. 타 계정이 실제 소유자의 ID를 알아도 잔액이 바뀌지 않았다.
- 실제 standalone HTTP 서버에서 익명 페이지→로그인 이동, 위조 쿠키 거부, 소유자 세션 조회, MCP 저장→DB→앱 조회, 앱 수정→MCP 전체 합계, 삭제→0 잔액, 재시도 및 다른 출처 차단을 검증했다.
- 실제 Google 로그인/콜백과 ChatGPT 모바일/데스크톱 연결은 운영 배포 후 실기기에서 확인해야 한다. 이 기록은 해당 외부 연결을 완료했다는 의미가 아니다.

## 남은 범위

KRW·단일 소유자 장부를 지원한다. 상환 방식 repayment_method는 기존 앱 모델에 없으므로 구조화된 미지원 오류로 반환한다. 최근 잔액 기준일 이전 잔액은 추정하지 않으며 미래 거래를 저장하지 않는다. 이력 테이블의 보관/관리 정책, 여러 소유자용 스키마 및 자산·분류·잔액 일괄 원복은 별도 범위다.

추가 테이블/인덱스 SQL, 배포 전 Google 설정, 롤백 시 주의점과 ChatGPT 재연결 순서는 [WORK_MCP.md](WORK_MCP.md)에 있다.
